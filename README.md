# 文物检索入门：关键词检索 + Embedding 向量检索 + 概念距离

> 给师弟的上手文档。目标：拿到一批文物描述文本后，能 **(1) 精确搜到含特定关键词的文物**，**(2) 按语义搜到"意思相近"的文物**，**(3) 量化两个文物概念之间有多近**。
>
> 所有代码都在本目录 `demo.py` 里实际跑过，文中的数字都是真实输出（模型 `BAAI/bge-small-zh-v1.5`，CPU 即可）。

---

## 0. 一页纸总结

| | 关键词检索（BM25） | 向量检索（Embedding） |
|---|---|---|
| 本质 | 字面匹配：查询里的词在文档里出现没有、出现几次、这个词稀不稀有 | 语义匹配：把文本变成向量，算向量夹角（余弦相似度） |
| 擅长 | 专有名词、器名、人名、地名、铭文原文（"宅兹中国"、"后母戊"） | 换个说法也能搜到（"喝酒用的" → 尊、壶）、跨概念联想（"音乐" → 编钟） |
| 不擅长 | 同义词、口语化提问——**词对不上就是 0 分** | 精确名词、别名、数字年代；**会给不相关的东西也打个"还行"的分** |
| 可解释性 | 强，能说清楚为什么命中 | 弱，是个黑盒距离 |
| 成本 | 极低，纯 CPU | 需要模型，大数据量需要向量库 |

**实战建议：两个都做，用 RRF 融合（第 6 节），最后可选再加一个 reranker（第 9 节）。**
**概念距离：不要直接比裸词，要比"带释义的句子"，并且只看相对排序、不看绝对值（第 7 节）。**

## 2. 数据准备：检索效果一半取决于这一步

### 2.1 数据格式

每件文物一行 JSON（JSONL），结构化字段 + 一段描述：

```json
{"id": "A03", "name": "何尊", "period": "西周早期", "material": "青铜",
 "desc": "西周早期青铜酒器，内底铸铭文122字，其中“宅兹中国”是“中国”一词最早的文字记载……"}
```

### 2.2 把结构化字段拼进检索文本

```python
d["text"] = f"{d['name']}。{d['period']}。{d['material']}。{d['desc']}"
```

原因：很多描述里不会重复写材质/年代，不拼进去，搜"西汉"就可能漏掉。
更严格的做法是 **结构化字段走过滤（filter），文本走检索**：比如"西汉的玉器"= 先 `period == 西汉 and material 含 玉` 过滤，再在结果里做语义排序。年代、材质、馆藏地这类字段，过滤永远比语义检索可靠。

### 2.3 文物数据特有的清洗问题（一定要处理）

| 问题 | 例子 | 处理 |
|---|---|---|
| 一物多名 | 铜奔马 = 马踏飞燕 = 马超龙雀；后母戊鼎 = 司母戊鼎 | 建**别名表**，入库时把别名都拼进文本，或查询时做同义词扩展 |
| 繁简 / 异体字 | 「銅」「铜」，「兰亭序」「蘭亭序」 | 统一转简体（`opencc`），原文另存一份用于展示 |
| 专名被切碎 | jieba 默认把"后母戊鼎"切成 后/母戊鼎，"马踏飞燕"切成 马踏飞/燕 | 自定义词典（2.4） |
| 年代表述不统一 | "公元前5世纪" / "春秋晚期" / "东周" | 规范成标准朝代字段 + 起止年份数值，用于过滤 |
| 器类术语不统一 | "尊"、"酒尊"、"盛酒器" | 参考行业规范或叙词表做受控词表（见 7.4） |

### 2.4 jieba 自定义词典

`data/user_dict.txt`，每行 `词 词频 词性`：

```
后母戊鼎 10 n
曾侯乙编钟 10 n
马踏飞燕 10 n
酒器 10 n
礼器 10 n
```

```python
jieba.lcut("后母戊鼎")             # 默认：['后', '母戊鼎']   ← 搜"后母戊鼎"会对不上
jieba.lcut("马踏飞燕")             # 默认：['马踏飞', '燕']
jieba.load_userdict("data/user_dict.txt")
jieba.lcut("曾侯乙编钟是乐器")   # ['曾侯乙编钟', '是', '乐器']
```

**词典是关键词检索最有性价比的优化**，花半天把馆藏名录、器类术语、朝代、遗址名导进去，效果立竿见影。

## 3. 关键词检索

### 3.1 最简单：精确包含 / 正则

查铭文、编号、专名时，**别上来就用模型**，字符串匹配最准：

```python
hits = [d for d in docs if "宅兹中国" in d["text"]]          # 精确短语
import re
hits = [d for d in docs if re.search(r"铭文\d+字", d["text"])]  # 模式匹配
```

缺点：没有排序，只有"有/没有"。

### 3.2 BM25：带排序的关键词检索

BM25 是搜索引擎（Elasticsearch / OpenSearch 默认）用的经典打分公式，直觉上就三条：

1. **词频（TF）**：查询词在文档里出现越多分越高，但有饱和（出现 10 次不会比 3 次高很多），参数 `k1`；
2. **逆文档频率（IDF）**：越稀有的词越值钱——"青铜"在青铜器库里到处都是，权重低；"鸟篆"很少见，权重高；
3. **长度归一化**：长文档天然词多，要打折，参数 `b`。

中文必须**先分词**，再喂给 BM25：

```python
import jieba
from rank_bm25 import BM25Okapi

STOPWORDS = set("的 了 是 和 与 在 于 为 以 及 其 之 一 有 等 由 而 、 ， 。".split())

def tokenize(text):
    return [w for w in jieba.lcut(text) if w.strip() and w not in STOPWORDS]

bm25 = BM25Okapi([tokenize(d["text"]) for d in docs])
scores = bm25.get_scores(tokenize("酒器"))   # 每个文档一个分数
```

实测（`uv run python3 demo.py "酒器"`）：

```
== 关键词 BM25 ==
    1.7563  四羊方尊（商代晚期，青铜）
    1.5658  何尊（西周早期，青铜）
    1.4532  莲鹤方壶（春秋中期，青铜）
```

三件描述里写了"酒器"的全部命中，排序也合理。**这是关键词检索的舒适区。**

### 3.3 关键词检索的两个典型翻车

**翻车 1：换个说法就搜不到**

```
查询：和音乐有关的文物    分词：['音乐', '有关', '文物']
== 关键词 BM25 ==
（空）
```

库里明明有曾侯乙编钟（"打击乐器"）和骆驼载乐俑（"乐俑围坐演奏"），但没有一件文档出现"音乐"两个字 → 0 分。

**翻车 2：被无关的词带偏**

```
查询：古代喝酒用的器物    分词：['古代', '喝酒', '用', '器物']
== 关键词 BM25 ==
    2.6171  后母戊鼎（商代晚期，青铜）
```

"喝酒"一词没有任何文档出现，唯一命中的是后母戊鼎描述里的"中国**古代**最重的青铜器"。—— BM25 只认字面，完全不懂你在问什么。

> 缓解办法：同义词扩展（"喝酒"→"酒器/饮酒/盛酒"）、更好的停用词表（把"古代""文物""器物"这类在文物库里没有区分度的词加进去）。但根本解法是第 4 节的向量检索。

## 4. Embedding 向量检索

### 4.1 原理一句话

Embedding 模型把一段文本映射成一个固定长度的向量（bge-small-zh 是 512 维，bge-m3 是 1024 维），**意思相近的文本，向量方向相近**。检索 = 算查询向量和所有文档向量的余弦相似度，取最大的 k 个。

$$\cos(q, d) = \frac{q \cdot d}{\|q\|\|d\|}$$

编码时设 `normalize_embeddings=True`，向量长度都是 1，**点积就等于余弦**，一个矩阵乘法搞定。

### 4.2 模型怎么选

| 模型 | 维度 | 大小 | 说明 |
|---|---|---|---|
| `BAAI/bge-small-zh-v1.5` | 512 | ~100MB | 中文小模型，CPU 秒级，**入门/原型首选** |
| `BAAI/bge-large-zh-v1.5` | 1024 | ~1.3GB | 中文效果更好 |
| `BAAI/bge-m3` | 1024 | ~2.2GB | 多语言、支持长文本（8192 token），中英文混合/外文文献选它 |
| 云端 API（Bedrock Titan / Cohere 等） | — | — | 不想自己部署时用，注意数据合规 |

> 文言文、古籍原文的效果会明显差于现代汉语描述。如果语料主要是古文，要专门做小规模评估（第 8 节），必要时用自己的数据微调。

### 4.3 代码

```python
from sentence_transformers import SentenceTransformer
import numpy as np

model = SentenceTransformer("BAAI/bge-small-zh-v1.5")
doc_emb = model.encode([d["text"] for d in docs], normalize_embeddings=True)  # (N, 512)

QUERY_PREFIX = "为这个句子生成表示以用于检索相关文章："   # bge-zh 推荐的查询前缀
def search(query, k=5):
    q = model.encode([QUERY_PREFIX + query], normalize_embeddings=True)[0]
    sims = doc_emb @ q
    top = np.argsort(-sims)[:k]
    return [(docs[i], float(sims[i])) for i in top]
```

**注意查询前缀**：bge-zh 系列是"非对称"训练的，短查询搜长文档时，查询加这个前缀、文档不加，效果更好。不同模型约定不同（e5 系列是 `query: ` / `passage: `），**用之前看一下模型卡**。

文档向量算一次存下来（`np.save`），不要每次查询都重新编码。

### 4.4 实测：关键词搜不到的，向量搜到了

```
查询：和音乐有关的文物
== 向量 Embedding（余弦） ==
    0.4636  曾侯乙编钟（战国早期，青铜）
    0.4587  唐三彩骆驼载乐俑（唐代，陶（三彩釉））
    0.4083  铜奔马（东汉，青铜）
    ...

查询：古代喝酒用的器物
== 向量 Embedding（余弦） ==
    0.5377  莲鹤方壶（春秋中期，青铜）
    0.5248  四羊方尊（商代晚期，青铜）
    0.5117  何尊（西周早期，青铜）
    ...
```

前两名都对了。但也要看到它的毛病：

- **永远有结果**：第 3 名开始（铜奔马 0.41）已经和音乐无关了，但分数并不低。向量检索不会说"没有"，**需要你自己定阈值或只看 top-k**。
- **分数差距很小**：正确答案 0.46 和错误答案 0.41 只差 0.05。余弦的绝对值没什么意义，**只看排序**。

### 4.5 数据量大了怎么办

| 规模 | 方案 |
|---|---|
| < 10 万条 | numpy 矩阵乘法暴力算，足够快 |
| 10 万 ~ 千万 | `faiss`（`IndexFlatIP` 精确 / `IndexHNSWFlat` 近似） |
| 需要服务化、过滤、增量更新 | Milvus / Qdrant / OpenSearch k-NN / pgvector |

```python
import faiss
index = faiss.IndexFlatIP(doc_emb.shape[1])   # IP = 内积，向量已归一化即余弦
index.add(doc_emb.astype("float32"))
sims, ids = index.search(q[None, :].astype("float32"), 5)
```

## 5. 关键词 vs 向量：什么时候用哪个

| 你的需求 | 用什么 |
|---|---|
| 搜"后母戊鼎"、"越王鸠浅"、某个馆藏编号 | 关键词（精确匹配/BM25） |
| 搜"和祭祀有关的器物"、"体现中外交流的文物" | 向量 |
| 搜"西汉的玉器" | **结构化过滤**（年代+材质），再排序 |
| 不确定用户会怎么问（大多数真实场景） | **混合检索**（第 6 节） |

## 6. 混合检索：RRF 融合

### 6.1 为什么不能直接把分数相加

BM25 分数是 0~几十，没有上限；余弦是 -1~1，而且通常挤在 0.3~0.6。直接相加，BM25 会完全压倒向量。归一化（min-max）也不稳，受极端值影响。

**RRF（Reciprocal Rank Fusion）只看名次，不看分数**：

$$\text{RRF}(d) = \sum_{\text{每路检索}} \frac{1}{k + \text{rank}(d)}, \quad k=60$$

```python
def rrf(result_lists, k=60, top=5):
    fused, by_id = {}, {}
    for results in result_lists:
        for rank, (doc, _) in enumerate(results, start=1):
            fused[doc["id"]] = fused.get(doc["id"], 0.0) + 1.0 / (k + rank)
            by_id[doc["id"]] = doc
    ranked = sorted(fused.items(), key=lambda x: -x[1])[:top]
    return [(by_id[i], s) for i, s in ranked]

hybrid = rrf([bm25_results, vector_results])
```

两路都排前面的文档会被显著抬高（"酒器"查询中，四羊方尊两路都第 1，融合后稳居第 1）。

### 6.2 一个要警惕的反例

```
查询：古代喝酒用的器物
== 混合 RRF ==
    0.0318  后母戊鼎（商代晚期，青铜）      ← BM25 被"古代"带偏的那条，融合后反而排第 1
    0.0164  莲鹤方壶（春秋中期，青铜）
    0.0161  四羊方尊（商代晚期，青铜）
```

原因：BM25 那一路只返回了 1 条（错的），它拿到 1/(60+1)；而向量那一路把后母戊鼎排在第 5，又给它加了 1/(60+5)。两路都有它，于是登顶。

**教训**：
1. 混合检索不是银弹，**任何一路的噪声都会进来**；
2. 停用词表要按领域定制——在文物库里"古代""文物""器物"都应该算停用词。实测把 `{古代, 文物, 器物, 用}` 加进停用词后，BM25 这一路返回空，混合结果退化为向量结果：莲鹤方壶 / 四羊方尊 / 何尊 排前三，问题消失；
3. 可以给两路加权（比如向量 0.7、BM25 0.3），或者给 BM25 设最低分阈值；
4. 最稳的做法是 RRF 召回 top-20~50，再用 **reranker 精排**（第 9 节）。

## 7. 概念距离：两个文物概念有多"近"

这是 embedding 的另一个用法：不是"搜文档"，而是**量化概念之间的语义距离**，比如"鼎"和"礼器"多近、"编钟"更像"乐器"还是"兵器"。可用于：构建概念图谱、给分类做推荐、找"相关概念"做查询扩展。

$$\text{距离} = 1 - \cos(\vec{a}, \vec{b})$$

### 7.1 基础做法：相似度矩阵

```python
terms = ["青铜器", "鼎", "酒器", "瓷器", "玉器", "书法"]
emb = model.encode(terms, normalize_embeddings=True)   # 概念对比是"对称"任务，不加查询前缀
sim = emb @ emb.T
```

实测（`uv run python3 demo.py --concept 青铜器 鼎 酒器 瓷器 玉器 书法`）：

```
　　　  青铜器      鼎    酒器    瓷器    玉器    书法
青铜器   1.000   0.483   0.521   0.633   0.597   0.273
鼎　　   0.483   1.000   0.412   0.500   0.436   0.377
酒器　   0.521   0.412   1.000   0.647   0.558   0.347
瓷器　   0.633   0.500   0.647   1.000   0.635   0.422
玉器　   0.597   0.436   0.558   0.635   1.000   0.396
书法　   0.273   0.377   0.347   0.422   0.396   1.000
```

大方向是对的："书法"和各类器物都远（0.27~0.42）。但细看有问题："鼎"和"青铜器"（0.483）反而不如"瓷器"和"青铜器"（0.633）近——鼎绝大多数就是青铜器啊。

### 7.2 实测发现的三个坑（重要）

我对一组概念对做了测试，两个模型、两种写法：

| 概念对 | small 裸词 | small 加"文物术语："前缀 | m3 裸词 | m3 加前缀 | 期望 |
|---|---|---|---|---|---|
| 编钟 - 乐器 | 0.351 | 0.580 | 0.500 | 0.698 | 应该近 |
| 编钟 - 兵器 | 0.370 | 0.587 | 0.460 | 0.668 | 应该远 |
| 兵器 - 乐器 | 0.583 | 0.717 | 0.700 | 0.854 | 应该远 |
| 马踏飞燕 - 铜奔马 | 0.526 | 0.679 | 0.507 | 0.697 | **同一件文物** |
| 马踏飞燕 - 燕子 | 0.594 | 0.739 | 0.605 | 0.721 | 应该远 |
| 青花瓷 - 瓷器 | 0.716 | 0.810 | 0.689 | 0.835 | 应该近 |
| 青花瓷 - 青铜器 | 0.637 | 0.769 | 0.633 | 0.795 | 应该远 |

**坑 1：裸词比的是"字面长相"，不是"含义"。**
"兵器-乐器"（0.583）远高于"编钟-乐器"（0.351），因为前者都带"器"字、结构相同。换成更大的 bge-m3 也一样（0.700 vs 0.500）。**换大模型解决不了这个问题。**

**坑 2：模型不懂别名。**
"马踏飞燕"和"铜奔马"是同一件文物，但模型认为"马踏飞燕"离"燕子"更近。这类知识模型没有，**只能靠别名表**。

**坑 3：绝对值没有意义。**
加个前缀，所有数值整体上移 0.1~0.2（各向异性），但相对关系基本不变。所以：
- 不要说"相似度 > 0.6 就算相关"这种跨模型、跨写法的阈值；
- **只在同一个模型、同一种写法下比较相对排序**；
- 要阈值的话，用你自己的标注数据去标定。

### 7.3 改进：用"释义"代替"裸词"

把每个概念写成一句定义（可以从词典、《中国大百科全书》、馆藏说明里摘，也可以让 LLM 起草后人工校对），再比较定义句的向量：

```python
gloss = {
    "编钟": "编钟：古代大型青铜打击乐器，由大小不同的钟按音高排列悬挂演奏",
    "乐器": "乐器：用来演奏音乐、发出乐音的器具",
    "兵器": "兵器：用于作战、杀伤敌人的武器，如刀剑戈矛",
    "鼎":   "鼎：古代烹煮肉食的器具，后成为象征权力的青铜礼器",
    "礼器": "礼器：古代用于祭祀、宴飨、典礼等礼仪活动的器物",
    "尊":   "尊：古代大中型盛酒器，侈口、长颈、圈足",
    "酒器": "酒器：古代盛酒、温酒、饮酒的器具",
}
e = model.encode([gloss["编钟"], gloss["乐器"]], normalize_embeddings=True)
print(e[0] @ e[1])
```

实测（bge-small-zh）：

| 概念对 | 裸词 | 释义句 |
|---|---|---|
| 编钟 - 乐器 | 0.351 | **0.585** |
| 编钟 - 兵器 | 0.370 | 0.512 |
| 鼎 - 礼器 | 0.440 | **0.734** |
| 尊 - 酒器 | 0.443 | **0.781** |
| 尊 - 兵器 | — | 0.439 |

"编钟"终于离"乐器"比离"兵器"近了，"尊-酒器"和"尊-兵器"拉开了 0.34 的差距。**释义句是做概念距离最简单有效的改进。**

### 7.4 更可靠的概念距离：结合知识体系

Embedding 距离是"统计上的相似"，学术上要严谨，最好和**人工构建的知识体系**互相印证：

- **受控词表 / 叙词表**：Getty AAT（Art & Architecture Thesaurus，有器类层级）、国内文物行业的藏品分类与登录规范（如《馆藏文物登录规范》WW/T 0017）。概念在层级树上的距离（最短路径、最近公共祖先深度）是可解释的"本体距离"。
- **知识图谱**：CIDOC-CRM 是博物馆领域的标准本体，可以把"文物-年代-材质-出土地-功能"连成图，用图距离或图嵌入。
- **组合用法**：用 embedding 找候选的"相关概念"（召回），用词表/图谱判断关系类型（上下位？同义？功能相关？）。

> 写论文时，"embedding 余弦相似度"只能叫"语义相似度"，别直接当成"概念的本体关系"，审稿人会问。

## 8. 怎么评估检索效果（别只看几个例子）

上面都是举例。真正判断好坏，要建一个**小的标注集**：50~100 个真实查询，每个查询人工标出相关文物。

```python
# eval_set: [{"query": "和音乐有关的文物", "relevant": {"A06", "A11"}}, ...]
def evaluate(search_fn, eval_set, k=5):
    recall, mrr = 0.0, 0.0
    for item in eval_set:
        ids = [d["id"] for d, _ in search_fn(item["query"], k)]
        rel = item["relevant"]
        recall += len(rel & set(ids)) / len(rel)                       # Recall@k：相关的找回了几成
        mrr += next((1 / (i + 1) for i, x in enumerate(ids) if x in rel), 0)  # MRR：第一个对的排第几
    n = len(eval_set)
    return {"Recall@k": recall / n, "MRR": mrr / n}

print(evaluate(kindex.search, eval_set))
print(evaluate(vindex.search, eval_set))
print(evaluate(lambda q, k: rrf([kindex.search(q, 20), vindex.search(q, 20)], top=k), eval_set))
```

查询要覆盖几类：**专名类**（"越王勾践剑"）、**属性类**（"西周的青铜酒器"）、**概念类**（"体现中外交流的"）、**别名类**（"马踏飞燕"）。分开统计，你会清楚看到关键词和向量各自强在哪。

每次改了分词词典、停用词、模型、融合权重，都跑一遍这个评估。**没有评估集的调参都是玄学。**

## 9. 进阶方向

1. **Reranker 精排**：先用混合检索召回 top-20~50，再用交叉编码器（如 `BAAI/bge-reranker-v2-m3`）把"查询+文档"成对打分重排。比纯向量准很多，代价是慢，只能用在少量候选上。
   ```python
   from sentence_transformers import CrossEncoder
   reranker = CrossEncoder("BAAI/bge-reranker-v2-m3")
   scores = reranker.predict([(query, d["text"]) for d, _ in candidates])
   ```
2. **长文本切块**：文物考古报告动辄几万字，要按段落切成 200~500 字的块分别编码，检索到块再回溯到文物。
3. **查询扩展**：用别名表或 LLM 把"马踏飞燕"扩展成"马踏飞燕 OR 铜奔马 OR 马超龙雀"再检索。
4. **领域微调**：有几千对"查询-相关文物"后，可以用 sentence-transformers 对 bge 做对比学习微调，对古文、专业术语提升明显。
5. **图文检索**：文物图片可以用 Chinese-CLIP 编码，实现"用文字搜图片"、"以图搜图"，和文本检索同一套 RRF 融合。
6. **RAG**：检索结果喂给大模型生成回答，就是"文物问答"系统。检索质量决定回答上限。

## 10. 常见坑 Checklist

- [ ] 专名有没有加进 jieba 词典？（`jieba.lcut("后母戊鼎")` 默认是 `['后', '母戊鼎']`）
- [ ] 停用词有没有加领域词（古代、文物、器物）？
- [ ] 繁简、异体字统一了吗？
- [ ] 别名表建了吗？embedding 不懂别名。
- [ ] 年代、材质、馆藏地用的是**过滤**而不是语义检索吗？
- [ ] 编码时 `normalize_embeddings=True` 了吗？没归一化，点积 ≠ 余弦。
- [ ] 查询前缀和模型匹配吗？（bge-zh / e5 各不相同）
- [ ] 文档向量缓存了吗？
- [ ] 是不是在用余弦绝对值当阈值？只看相对排序，或用标注数据标定。
- [ ] 概念距离用的是释义句还是裸词？
- [ ] 有没有评估集？改动前后跑过对比吗？
